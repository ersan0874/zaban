# فاز ۱۸ — تولید محتوای آموزشی با هوش مصنوعی (Gemini)

## هدف
مدیر هر نوع فایل آموزشی (PDF متنی یا اسکن‌شده، عکس، Word، متن؛ هر زبانی) را آپلود می‌کند.
Gemini محتوا را می‌خواند و ۲ تا ۳ **پیشنهاد ساختار** (فصل ← زیرفصل ← درس) می‌دهد. مدیر یکی را انتخاب می‌کند.
سپس برای هر درس **نکته‌های کوتاه آموزشی** و **سؤال‌های چند نوع** ساخته می‌شود. مدیر بازبینی و منتشر می‌کند و محتوا مستقیم در اپ استفاده می‌شود.
باید برای هر درسی کار کند (فعلاً واژگان کنکور، در آینده مثلاً کتاب ریاضی).

## تصمیم‌های کاربر (۲۰۲۶-۱۰-۰۲)
| موضوع | تصمیم |
|---|---|
| دامنه | دامنه‌آزاد؛ فرمول‌ها با LaTeX |
| ساختار | AI چند پیشنهاد؛ مدیر انتخاب/ویرایش |
| متن آموزشی | دارد، نکته‌وار و کوتاه |
| سؤال‌ها | ۹ نوع قبلی + تشریحی، صحیح/غلط، پاسخ کوتاه؛ ماژولار |
| تشریحی | Gemini با پاسخ مرجع نمره می‌دهد |
| بازبینی | دو مرحله: انتخاب ساختار + تأیید محتوا |
| ورودی | همه زبان‌ها و قالب‌ها |
| مدل | Gemini با کلید رایگان |
| شبکه | سرور ایران؛ تونل AI بعداً و فقط با درخواست کاربر ساخته می‌شود |

## خط لوله
1. آپلود (`POST /api/admin/content/jobs`، multipart) → فایل‌ها در `UPLOAD_DIR`
2. استخراج: PDF (تکه‌های ۸ صفحه‌ای) و عکس → Gemini به Markdown + LaTeX با نشانگر صفحه؛ Word با `mammoth`؛ متن مستقیم
3. تقسیم به «بلوک‌های منبع» شماره‌دار (~۹۰۰ کاراکتر)
4. پیشنهاد ساختار: ۲–۳ outline؛ هر درس به بازه بلوک‌ها اشاره می‌کند → **بازبینی ①**
5. هر درس: نکته‌ها + اصطلاحات کلیدی + سؤال‌ها (تعداد هر نوع از تنظیمات job)
6. کنترل کیفیت: اسکیمای JSON → `validate()` ماژول → بازسازی موارد خراب (تا ۲ دور) → پاس بازبین AI؛ موارد مشکوک «needs_review»
7. **بازبینی ②** در پنل: ویرایش نکته/سؤال، تأیید، حذف، «دوباره بساز»
8. انتشار در یک تراکنش: Course/Section/Unit/Lesson(notes)/Exercise؛ در دامنه `language` اصطلاحات → `Word` (برای SRS)

## زیرساخت
- `src/ai/llm/`: رابط `LlmProvider` + `GeminiProvider` (خروجی JSON Schema، rate limit، retry، fallback به مدل lite، تشخیص سقف روزانه)
- `src/questions/registry/`: یک تعریف برای هر نوع سؤال (schema تولید، `validate`، `grade`)
- `src/content/`: entityها، صف BullMQ (`content-pipeline`)، سرویس‌ها و API ادمین
- `src/worker.ts` + سرویس `worker` در Docker
- پنل ادمین: `/content` و `/content/[id]`
